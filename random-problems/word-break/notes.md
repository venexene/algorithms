# Word Break

## Решение

### Bottom-up DP по префиксам строки — O(n²), O(n)

`dp[i]` = можно ли разбить префикс `s[:i]` на слова из словаря.

- База: `dp[0] = true` (пустой префикс).
- Переход: `dp[i] = true`, если существует `j < i` такой, что `dp[j] == true` и `s[j:i] ∈ dict`.
- Ответ: `dp[n]`, где `n = len(s)`.

Идея: наращиваем строку слева направо; на каждом шаге спрашиваем, не заканчивается ли здесь слово, при условии что всё до него уже разбито.

## Что важно запомнить

- **Переход — «разрезать в точке j»** — `dp[j] && s[j:i] ∈ dict`. Правая часть `s[j:i]` должна быть словом, левая — уже разбитой.
- **Альтернативный переход — по словарю** — `dp[i] = true`, если `i >= len(w) && dp[i-len(w)] && s[i-len(w):i] == w`. Быстрее при маленьком словаре.
- **Паттерн «DP по строке/сегментации»** — новый для меня, не был в основном плане. Отличие от других DP: состояние — позиция в строке, а не элемент массива.
- **Backtracking здесь экспоненциальный** — O(2ⁿ) из-за повторного пересчёта одних и тех же позиций. DP устраняет повторы через `dp`-массив.

## Что пошло не так

1. **Bruteforce с TLE** — рекурсия `wordBreakAdd(s, i)` без мемоизации пересчитывала одни и те же состояния, O(2ⁿ).
2. **Состояние `(s, i)` неудобно для мемоизации** — из-за срезов строки состояние размазывалось; правильный ключ — один индекс `start` в исходной строке.
3. **Итог** — заменил на bottom-up DP, O(n²), O(n).
