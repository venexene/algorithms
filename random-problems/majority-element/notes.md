# Majority Element

## Решение

### 1. Хеш-таблица (частоты) — O(n), O(n)

Считаем вхождения каждого элемента в `map[int]int`, затем находим элемент с частотой `> n/2`. Просто и понятно, но тратит O(n) памяти.

### 2. Алгоритм Бойера — Мура — O(n), O(1)

Поддерживаем кандидата `major` и счётчик `c`. Один проход:

- `c == 0` → берём текущий элемент кандидатом, `c = 1`;
- `n == major` → `c++`;
- иначе → `c--`.

В конце кандидат — это majority-элемент.

**Почему работает:** majority встречается чаще, чем все остальные элементы вместе взятые, поэтому «чужие» элементы не могут обнулить его счётчик к концу массива.

## Что важно запомнить

- **Бойер — Мур** — классический приём поиска элемента большинства за O(n) времени и O(1) памяти, без сортировки и мапы.
- **Механика «кандидат + счётчик»**: чужой элемент съедает один голос; большинство всегда выживает.
- **Ограничение**: работает только когда majority строго больше `n/2`. Если гарантии нет — нужен второй проход для проверки кандидата.
- **Простая альтернатива** — мапа частот: O(n), O(n). Для задачи тоже проходит, но Бойер — Мур экономнее по памяти.
- Ещё вариант — сортировка + элемент посередине: O(n log n), медленнее.

## Что пошло не так

- Сам до алгоритма не додумался — это неочевидный приём, и это нормально. Решение через мапу интуитивно, но Бойер — Мур стоит запомнить как отдельный паттерн.
