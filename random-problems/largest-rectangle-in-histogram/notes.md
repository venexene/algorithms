# Largest Rectangle in Histogram

## Инсайт

Не нужно перебирать все возможные прямоугольники. Вместо этого можно считать каждый столбец минимальной высотой некоторого прямоугольника.

Для столбца `i` высоты `heights[i]` прямоугольник может расширяться влево и вправо, пока не встретится столбец **строго ниже**. Если известны ближайшие меньшие элементы `left[i]` и `right[i]`, то:

```text
width = right[i] - left[i] - 1
area  = heights[i] * width
```

Остаётся найти эти границы для всех столбцов за линейное время монотонным стеком.

## Решение

### Два прохода с монотонным стеком — O(n), O(n)

Стек хранит индексы столбцов и поддерживается так, чтобы их высоты возрастали снизу вверх.

1. Идём слева направо. Пока на вершине высота `>= heights[i]`, удаляем индекс: он не может быть ближайшим строго меньшим для текущего столбца. Оставшаяся вершина — `left[i]`; если стек пуст, граница равна `-1`.
2. Очищаем стек и идём справа налево аналогично. Вершина после удалений — `right[i]`; если стек пуст, граница равна `n`.
3. Для каждого `i` считаем площадь по формуле и выбираем максимум.

## Что важно запомнить

- Прямоугольник с высотой `heights[i]` охватывает индексы от `left[i] + 1` до `right[i] - 1`, поэтому ширина именно `right - left - 1`.
- Границы виртуальные: `-1` слева и `n` справа. Благодаря этому крайние столбцы обрабатываются без отдельных веток.
- В условии удаления из стека используется `>=`, а не `>`: одинаковые высоты надо пропустить, чтобы границей остался только **строго меньший** столбец.
- Каждый индекс добавляется в стек один раз и удаляется не более одного раза, поэтому оба прохода суммарно `O(n)`.
- Пустой массив корректно даёт `0`: цикл вычисления площадей не выполнится.

## Что пошло не так

Самостоятельно не удалось прийти к решению. Ключевой пропущенный шаг — сменить взгляд с «какие прямоугольники можно построить» на «насколько далеко может расшириться прямоугольник, для которого этот столбец — минимальный». После этого задача сводится к поиску ближайших меньших элементов — стандартному применению монотонного стека.

## Альтернатива

Можно вычислять ответ за один проход: при появлении более низкого столбца выталкивать из стека более высокие и сразу считать их максимальную площадь. В конце добавляют виртуальный столбец высоты `0`, чтобы вытолкнуть оставшиеся элементы. Решение использует меньше памяти, но вариант с двумя массивами границ проще для первого понимания и отладки.
