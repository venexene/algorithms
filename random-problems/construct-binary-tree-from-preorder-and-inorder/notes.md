# Construct Binary Tree from Preorder and Inorder Traversal

## Решение

### Финальное: замыкание + глобальный `idx` — O(n), O(n)

Первый элемент preorder — всегда корень. По позиции корня в inorder (`mid`) делим массив на два поддерева:

- левое — элементы inorder в `[left, mid-1]`;
- правое — в `[mid+1, right]`.

Preorder идёт как «корень → левое поддерево → правое», поэтому единый счётчик `idx` двигается сам: рекурсивный вызов для левого поддерева «съедает» ровно свои элементы, и `idx` встаёт на начало правого.

### Изначальное: проброска `i` + явная проверка границ

Старый вариант передавал индекс `i` в параметр и возвращал его из `dfs`. Границы проверял вручную: попадает ли следующий preorder-элемент в левую/правую часть по позиции в inorder (`left <= pos && pos < mid` и `mid < pos && pos <= right`), плюс проверки `i >= len(preorder)`.

## Почему в финальной версии не нужны проверки границ

- База `left > right` возвращает `nil` — это и есть проверка: пустой диапазон в inorder = пустое поддерево.
- Проверки `pos < mid` / `pos > mid` из старой версии уже зашиты в суженные диапазоны `[left, mid-1]` и `[mid+1, right]`.
- Проверка `i >= len(preorder)` не нужна: каждый узел создаётся ровно один раз, рекурсия останавливается на `left > right` раньше, чем `idx` дойдёт до конца.

## Что важно запомнить

- **Первый элемент preorder — корень**; `mid = inorderMap[rootVal]` делит inorder на поддеревья.
- **Preorder = корень → левое → правое** — поэтому один глобальный `idx` корректно раздаёт элементы.
- **`var dfs` перед присваиванием** — Go не даёт рекурсивной функции-литералу ссылаться на себя через `:=`; сначала объявляем переменную, потом присваиваем.
- **База `left > right`** — пустой диапазон, возврат `nil`.
- Map `value → index` для inorder даёт O(1) поиск позиции, итог O(n) вместо O(n²).

## Что пошло не так

- Изначально сделал проброску индекса `i` через параметр и возврат — работало, но громоздко: ручные проверки `pos < mid` / `pos > mid` и `i >= len(preorder)`.
- Не сразу понял, что в финальной версии границы уже всё проверяют через `left > right`, а не через позиции в preorder.
- Спрашивал, зачем `var dfs` — это ограничение Go для рекурсивных замыканий.
