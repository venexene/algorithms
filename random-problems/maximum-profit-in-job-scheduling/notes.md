# Maximum Profit in Job Scheduling

## Инсайт

Это задача о взвешенном выборе непересекающихся интервалов. Для каждой работы есть два варианта: взять её и прибавить лучшую прибыль от всех совместимых предыдущих работ или пропустить её.

Если отсортировать работы по времени окончания, все работы, которые могут стоять перед текущей, уже обработаны. Остаётся быстро находить последнюю работу с `endTime <= startTime` текущей.

## Решение

### Sort + DP + binary search — O(n log n), O(n)

1. Собрать работы в структуры `(start, end, profit)` и отсортировать их по `end`.
2. `dp[i]` — максимальная прибыль, которую можно получить, рассматривая работы от `0` до `i` включительно.
3. Для работы `i` бинарным поиском найти максимальный индекс `prev`, для которого `jobs[prev].End <= jobs[i].Start`.
4. Переход:

   ```text
   dp[i] = max(dp[i - 1], jobs[i].Profit + dp[prev])
   ```

   Если совместимой предыдущей работы нет, её вклад равен `0`.

## Что важно запомнить

- Сортировать нужно по **времени окончания**: тогда `dp[prev]` уже хранит оптимальный ответ для всех допустимых предыдущих работ.
- Условие совместимости — `previous.End <= current.Start`. Работы `[1, 3]` и `[3, 5]` не пересекаются и могут быть взяты вместе.
- Бинарный поиск ищет не просто любую совместимую работу, а **последнюю**: она даёт доступ к оптимуму на максимально длинном подходящем префиксе.
- Нельзя выбирать только самую прибыльную доступную работу: локально выгодный выбор может перекрыть несколько работ с большей суммарной прибылью.
- Наивный поиск `prev` проходом назад для каждой работы даёт `O(n²)`; бинарный поиск снижает решение до `O(n log n)`.

## Краевые случаи

- У текущей работы нет совместимой предыдущей: прибыль равна только `jobs[i].Profit`.
- Несколько работ заканчиваются или начинаются в одно время: равенство в `End <= Start` важно сохранить.
- При одном задании ответ — его прибыль.
