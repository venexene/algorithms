# Find All Anagrams in a String

## Решение

### Sliding window + `map[byte]int` + transitions counter — O(n), O(k)
Фиксированное окно длины `len(p)`. Карта частот символов `p`. Счётчик `c` — число уникальных символов `p`, чьи частоты ещё не полностью набраны в окне. Когда `c == 0` — окно является анаграммой, записываем `left`.

Механика:
- Строим карту частот; `c = len(set)`.
- Вложенным циклом `for right-left < len(p)` добираем окно до нужного размера: для символа из карты уменьшаем частоту; если она перешла `1 → 0`, `c--`.
- `c == 0` → `append(left)`.
- Сдвигаем левую границу: если частота символа была `0` (переход `0 → 1`), `c++`, затем увеличиваем частоту.

## Что важно запомнить
- `c` — число уникальных символов (`len(set)`), не `len(p)`. На дубликатах `len(p)` никогда не даст 0.
- Переходы через 0: `c--` при `1 → 0`, `c++` при `0 → 1`. Не на каждом изменении счётчика.
- «Лишние» вхождения символа уводят частоту в минус, и `c` при этом не трогается — это корректно.
- Проверка `_, ok := map[ch]` отличает «символа нет в p» (игнорируем) от «символ в p».
- Символы не из `p` занимают место в окне, но не влияют на `c` — фиксированный размер окна учитывает это сам.
- Для 26 строчных букв идиоматичнее `[26]int` (прямой доступ, без хеширования), но тогда теряется `ok` — нужен второй массив признаков `inP [26]bool`.

## Что пошло не так
1. `c = len(p)` (общее число символов) — на дубликатах (`p="aab"`) `c` не мог дойти до 0: каждый уникальный символ «закрывается» максимум один раз, итог всегда пустой результат. Исправил на `len(set)`.
2. Префилл-цикл дублировал логику добавления символа и брал границу по `len(runesP)` — при смешении байтов и рун был риск выхода за границы. Убрал дублирование вложенным циклом.
3. `[]rune` для строчных латинских букв избыточен — перешёл на `byte`.
4. Итог: решение корректно после исправления инициализации счётчика.
