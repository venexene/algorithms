# String to Integer (atoi)

## Решение

### Один проход + клампинг переполнения — O(n), O(1)
Один указатель `i` по строке:
1. Пропускаем ведущие пробелы.
2. Обрабатываем знак `+`/`-`.
3. Читаем цифры, пока они идут; на первом не-цифровом символе возвращаем `res*sign`.
4. Если цифр не было — возвращаем 0 (`res` так и останется 0).
5. Клампинг к `[-2^31, 2^31-1]` двумя защитами:
   - пред-проверка `res > maxVal/10` — останавливает накопление до переполнения `int64`;
   - финальный кламп после `res *= sign` — ловит пограничный случай `res == maxVal/10`, где решает последняя цифра.

## Что важно запомнить
- `res` — всегда неотрицательная «магнитуда», знак применяется в конце и в момент возврата на не-цифре.
- Две защиты от переполнения решают разные задачи:
  - пред-проверка `res > maxVal/10` — защита от переполнения самого `int64` (иначе на длинных строках `res` обернётся, и финальный кламп сравнит мусор);
  - финальный кламп — граница `res == maxVal/10`, где решает последняя цифра (`2147483648` vs `2147483649`).
- `-1 << 31` и `1<<31 - 1` — целые константы вместо `math.Pow(2,31)` (float64 + конвертация — плохой паттерн, не портабелен на 32-бит).
- Приоритет операторов: `-1 << 31` = `(-1) << 31`; `1<<31 - 1` = `(1<<31) - 1`.
- Работа с байтами `s[i]`, а не `[]rune` — строка ASCII, память O(1).
- Без цифр (`"+"`, `"-"`, `"   "`, `"abc"`) — `res` остаётся 0, возвращаем 0.
- Спецификация говорит «whitespace», но тесты используют только пробел — скипаем `' '`.

## Что пошло не так
1. `math.Pow(2, 31)` для границ — float64 с конвертацией, считался в цикле на каждой итерации. Заменил на `-1<<31` / `1<<31-1`.
2. `[]rune(s)` — лишняя аллокация, заменил на байты.
3. Лишний цикл пропуска ведущих нулей — основной цикл и так корректно обрабатывает нули.
4. Едва не убрал пред-проверку `res > maxVal/10`, посчитав её дублем финального клампа. На самом деле она обязательна: без неё `res` (int64) переполняется на длинных строках и финальный кламп возвращает неверное значение (например `-2147483648` вместо `2147483647`).
