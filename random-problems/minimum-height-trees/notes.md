# Minimum Height Trees

## Решение

### Leaf peeling (топологическая обрезка) — O(n), O(n)
Срезаем листья слой за слоем. Когда остаётся 1–2 узла — это и есть минимальные по высоте корни.

Идея: центр дерева — середина диаметра. Лист не может быть центром (кроме `n ≤ 2`), поэтому убираем листья. После среза появляются новые листья — на следующем слое. Последние оставшиеся узлы и есть центры.

Механика:
- Неориентированный список смежности `[][]int` + массив степеней `degree` (считаем на лету при добавлении ребра).
- Стартовая очередь — все узлы со степенью 1.
- Пока `remaining > 2`: фиксируем `layerSize := len(queue)`, вычитаем его из `remaining`, обрабатываем ровно этот слой: для каждого соседа `degree--`, при `degree == 1` сосед уходит в `nextQueue`. Затем `queue = nextQueue`.
- Ответ — то, что осталось в `queue`.

## Альтернативные решения

### 1. Bruteforce: BFS/DFS из каждого узла — O(n²), O(n)
Для каждого узла считаем высоту дерева (максимальную глубину) BFS/DFS. Берём узлы с минимальной высотой. Просто и наглядно, но при `n` до 2·10⁴ не проходит по времени.

### 2. Диаметр через два BFS/DFS + массив родителей — O(n), O(n)
1. BFS/DFS из произвольного узла `0` → находим самый дальний узел `A`.
2. BFS/DFS из `A` → находим самый дальний узел `B`. Путь `A→B` — диаметр.
3. Восстанавливаем путь по массиву `parent` и берём середину: 1 узел при нечётной длине, 2 при чётной.

### 3. Диаметр через DP на дереве (два самых длинных пути вниз) — O(n), O(n)
Для каждого узла держим два самых длинных пути вниз; их сумма через узел — кандидат в диаметр. Глобально берём максимум. Рабочий, но при реконструкции пути срезами легко наступить на алиасинг, нужны `visited`/`parent`.

## Что важно запомнить
- Центры дерева — середина диаметра: 1 узел (нечётная длина) или 2 (чётная).
- Leaf peeling: режем листья **слоями**, а не по одному — иначе слои смешиваются и центр «уезжает».
- `degree` — «живая» степень: уменьшается при обрезке соседей. `len(tree[v])` не меняется, его для этого использовать нельзя.
- `degree == 1` — триггер нового листа (остался один сосед). Дублей нет: степень убывает монотонно и проходит через 1 один раз.
- Остановка `remaining > 2`: в конце в очереди ровно 1–2 узла.
- Неориентированное дерево: добавляем рёбра в обе стороны.
- Краевые случаи: `n == 1 → [0]`, `n == 2 → оба узла`.

## Что пошло не так
1. Первая попытка — диаметр через рекурсивную сборку пути:
   - рёбра добавлялись только в одну сторону (`edge[0] → edge[1]`) → DFS не обходил всё дерево, диаметр находился неверно;
   - не было `visited` → при добавлении обратных рёбер был бы бесконечный цикл;
   - произвольный корень `edges[0][0]` → паника при `n == 1`;
   - `return append(maxPath1, node)` — алиасинг среза, портил соседние пути.
2. Возврат центров: ветки чётности перепутаны и индексы неверные (`[L/2+1]` вместо середины).
3. Итог: перешёл на leaf peeling — он убирает все эти ловушки (нет рекурсии, нет реконструкции пути, обе стороны ребра естественны).
