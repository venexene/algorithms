# Merge Intervals

## Решение

### Сортировка по началу + жадное слияние — O(n log n), O(n)

Сортируем интервалы по `start`, затем проходим по массиву: для каждого интервала с начала `start` внутренним циклом расширяем `end`, пока следующий интервал пересекается (`intervals[j+1][0] <= end`). Каждый раз обновляем `end = max(end, intervals[j][1])`. Готовый диапазон `[start, end]` кладём в результат.

## Что важно запомнить

- **Сравнивать с бегущим максимумом конца** — условие `intervals[j+1][0] <= end` и обновление `end = max(end, intervals[j][1])`. Ключевой инсайт: проверять пересечение нужно с **максимальным** `end`, а не с концом предыдущего интервала. Пример, где это важно: `[[1,10],[2,3],[4,5]]`.
- **`<=` объединяет касающиеся интервалы** — `[1,2]` и `[2,3]` сливаются в `[1,3]` (по условию LeetCode это пересечение).
- **Сортировка по `start` достаточна** — по `end` отдельно сортировать не нужно. После сортировки по началу все старты неубывающие, поэтому как только `next.start > end`, дальше смотреть смысла нет.
- **Каждый результат — свежий слайс** — `[]int{start, end}` создаётся заново, иначе все элементы результата будут ссылаться на один и тот же слайс.
- **`make([][]int, 0, len(intervals))`** — предвыделение капасити, чтобы `append` не реаллоцировал лишний раз.
- **`slices.SortFunc` + `cmp.Compare`** — современная сортировка (Go 1.21+), `cmp.Compare` безопасен от переполнения int.
- **Мутация входа** — сортировка in-place меняет порядок `intervals`. Для LeetCode допустимо, но это сайд-эффект.
