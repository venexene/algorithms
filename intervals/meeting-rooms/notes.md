# Meeting Rooms

## Решение

### Сортировка по началу + проверка соседей — O(n log n), O(1)

Сортируем интервалы по `start`, затем идём по соседним парам: если `intervals[i].start < intervals[i-1].end` — встречи пересекаются, вернуть `false`. Иначе все встречи можно посетить.

## Что важно запомнить

- **Условие пересечения** — `start < prev.end`. Соседние встречи с `end == start` (`{0,5}, {5,10}`) не конфликтуют — это корректно по условию задачи.
- **`slices.SortFunc` + `cmp.Compare`** — современный способ сортировки (Go 1.21+). `cmp.Compare` безопасен от переполнения int, в отличие от `a.start - b.start`.
- **Мутация входного слайса** — `slices.SortFunc` сортирует in-place, исходный порядок `intervals` теряется. Для LeetCode не критично, но в реальном коде — сайд-эффект (нужна копия, если важен исходный порядок).
- **`sort.Slice` тоже применим** — `sort.Slice(intervals, func(i, j int) bool { return intervals[i].start < intervals[j].start })`, но он использует рефлексию (`reflect.Swapper`), поэтому медленнее и менее типобезопасен. Не путать с `sort.Sort`, который требует реализации `sort.Interface` (`Len`, `Less`, `Swap`).
- **Нижняя граница** — O(n log n) для сортировочного подхода. Brute-force O(n²) не нужен.
- Крайние случаи: пустой слайс и одна встреча → `true`.
