# Summary Ranges

## Решение

### Two pointers (внешний `i` + внутренний `j`) — O(n), O(n)

Проходим по массиву: `i` — начало диапазона, внутренний цикл двигает `j` вперёд, пока числа идут подряд (`nums[j+1] == nums[j]+1`). Диапазон задаётся парой `(i, j)`; дальше либо одиночка (`start == nums[j]`), либо `"start->end"`. После записи перескакиваем `i = j + 1`.

## Что важно запомнить

- **Диапазон — это пара `(i, j)`** — внешний указатель на начало, внутренний на конец. Никакой отдельной переменной `end` не нужно.
- **Условие непрерывности** — `nums[j+1] == nums[j]+1`, а не `nums[i]-1 != nums[i-1]` (читается очевиднее, нет вопросов про переполнение).
- **Один блок форматирования** — без дублирования логики `if start == end` в цикле и после него.
- **`strconv.Itoa` везде** — единообразно и быстрее, чем смесь с `fmt.Sprintf` (Sprintf медленнее из-за форматирования).
- Крайние случаи: пустой массив → `[]string{}`, один элемент → `"x"`, два подряд → `"x->y"`, два с разрывом → `"x","y"`.

## Что пошло не так

1. **Первая версия**: `nums[i] - 1 != nums[i-1]` — условие разрыва работало, но читалось хуже.
2. **Первая версия**: дублирование блока `if start == end ... else ...` в цикле и после цикла.
3. **Первая версия**: лишний `continue` в ветке разрыва (конец тела цикла).
4. **Первая версия**: смесь `strconv.Itoa` и `fmt.Sprintf` — приведено к единому стилю.
