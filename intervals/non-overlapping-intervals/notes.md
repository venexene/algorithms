# Non-overlapping Intervals

## Решение

### Жадный: сортировка по началу + минимальный конец — O(n log n), O(1)

Сортируем интервалы по `start`. Идём по массиву, держим `prevEnd` — конец последнего оставленного интервала. Если `intervals[i][0] < prevEnd` — пересечение: удаляем более длинный, то есть оставляем интервал с меньшим концом (`prevEnd = min(prevEnd, intervals[i][1])`), счётчик `res++`. Иначе — интервал не пересекается, `prevEnd = intervals[i][1]`.

## Что важно запомнить

- **Сравнивать с `prevEnd`, а не с `intervals[i-1][1]`.** `prevEnd` — это конец последнего *оставленного* интервала, а не просто предыдущего в массиве. Ошибка `intervals[i][0] < intervals[i-1][1]` даёт неправильный ответ (например, `[[1,2],[1,3],[2,3]]` → 2 вместо 1).
- **Жадный выбор: удаляем более длинный** — при пересечении оставляем интервал с меньшим концом (`min`). Это оставляет максимум места для остальных и гарантирует минимальное число удалений.
- **Сортировка по `start`** — достаточно, сортировать по `end` не обязательно (равнозначный вариант — сортировать по `end` и считать непересекающиеся).
- Порядок при равных `start` не важен — алгоритм корректен при любом порядке в сортировке.
- Пустой вход по условию LeetCode невозможен (`1 <= len`), но `intervals[0]` без проверки запаникует на пустом слайсе.

## Что пошло не так

1. **`intervals[i][0] < intervals[i-1][1]`** — сравнение с концом предыдущего элемента вместо `prevEnd`; ломалось на цепочках пересечений (например, `[[1,2],[1,3],[2,3]]`).
