# Insert Interval

## Решение

### Линейный 3-фазный проход — O(n), O(n)

Вход уже отсортирован и не пересекается, поэтому сортировка не нужна. Проходим по массиву один раз:

1. **До слияния** — все интервалы со `end < newInterval[0]` (строго до `newInterval`) добавляем без изменений.
2. **Слияние** — все интервалы со `start <= newInterval[1]` пересекаются или касаются: расширяем `newInterval` через `min`/`max`.
3. **После слияния** — добавляем `newInterval` и весь оставшийся хвост.

## Что важно запомнить

- **Два строгих условия** — границы фаз держатся на `end < newInterval[0]` (строго меньше) и `start <= newInterval[1]` (с `<=`). Касающиеся интервалы (`[1,2]` и `[2,5]`) уходят в слияние, а не в фазы «до/после».
- **Границы двигаются через `min`/`max`** — `newInterval[0] = min(newInterval[0], intervals[i][0])`, аналогично для конца. Это и есть «слияние диапазона».
- **Бинарный поиск здесь не нужен** — он ищет одну позицию, а задача про нахождение левой и правой границы слияния. К тому же построение результата всё равно O(n), так что бинарный поиск не даёт выигрыша по асимптотике.
- **Компактная запись срезами** — `append(res, intervals[:i]...)` и `append(res, intervals[i:]...)` вместо ручных циклов. `intervals[:0]` и `intervals[n:]` — валидные пустые срезы.
- **Мутация `newInterval`** — в фазе 2 меняем переданный слайс (сайд-эффект для вызывающего). Для LeetCode не критично.

## Что пошло не так

1. **Попытка бинарного поиска** — обновления `left = i` / `right = i` без `+1`/`-1` зацикливались (пример: `left=0, right=1` → `i=0` → `left=0` бесконечно).
2. **`break` по «интервал содержит начало»** — не покрывал случай, когда `newInterval[0]` попадает в зазор между интервалами.
3. **Неверные ранние `return`** — вставка в начало/конец без слияния ломалась на касающихся интервалах (например, `newInterval=[0,2]` и `[[1,3],[5,7]]` должно слиться в `[[0,3],[5,7]]`).
4. Итог: перешёл на линейный 3-фазный проход — он проще и не требует этих краевых случаев.
