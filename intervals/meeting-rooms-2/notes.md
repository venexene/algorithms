# Meeting Rooms II

## Решение

### Sweep-line: раздельная сортировка starts и ends — O(n log n), O(n)

Сортируем начала и концы в два отдельных массива. Двумя указателями идём по временной шкале: на каждое начало — если ближайший конец `ends[j] <= starts[i]`, сначала освобождаем комнату (`actRooms--`), потом занимаем (`actRooms++`); иначе просто занимаем новую (`actRooms++`). Ответ — максимум `actRooms` за весь проход.

### Альтернатива: сортировка по началу + min-heap концов — O(n log n), O(n)

Сортируем интервалы по `start`. Min-heap хранит концы встреч, которые сейчас занимают комнаты. Для каждого интервала по порядку:

- если верхушка кучи (самый ранний конец) `<= start` — комната освободилась, `heap.Pop`;
- кладём `end` текущей встречи в кучу;
- размер кучи — текущее число занятых комнат, обновляем максимум.

## Что важно запомнить

- **Раздельная сортировка** — достаточно отсортировать `starts` и `ends` отдельно, сами интервалы сортировать не нужно.
- **Tie-break `ends[j] <= starts[i]`** — встреча, заканчивающаяся ровно в момент начала следующей, сначала освобождает комнату. Back-to-back (`[1,2],[2,3]`) → 1 комната.
- **`actRooms--` → `actRooms++` — net-zero**, когда комната освобождается и тут же занимается. Эквивалентно каноническому sweep-line; на максимум не влияет.
- **На `i=0` декремент не срабатывает** — `ends[0] > starts[0]` всегда (конец интервала больше его начала), поэтому `actRooms` не уходит в минус и выхода за границы `ends` нет.
- **Сложность** — O(n log n) по времени (две сортировки), O(n) по памяти (два вспомогательных массива).
- Альтернатива той же сложности — min-heap по концам (`container/heap`), но sweep-line проще и без кучи.
