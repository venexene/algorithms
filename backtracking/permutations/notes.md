# Permutations

## Решение

### 1. Swap in-place — O(n!), O(1) доп. на узел (лучший)

Переставляем элементы местами прямо в `nums`, без новых слайсов.

Идея: на позицию `start` по очереди ставим каждый из оставшихся элементов (swap), рекурсивно заполняем хвост, возвращаем обратно.

### 2. Удаление элемента — O(n!·n)

На каждом шаге строим `newNums` без выбранного элемента и рекурсируем. Проще для понимания, но O(n) копирования на узел.

### 3. Visited map — O(n!·n)

Храним `visited`, рекурсируем по непосещённым, клонируя мапу на каждом шаге. Понятно, но `maps.Clone` на каждом узле — самая медленная из трёх.

| | Swap | Удаление | Visited |
|---|------|----------|---------|
| Доп. работа на узел | O(1) | O(n) copy | O(n) clone |
| Аллокации | только финальная копия | каждый узел | каждый узел |
| Читаемость | средняя | хорошая | хорошая |

## Что важно запомнить

- **Swap-подход — стандарт для Permutations.** Нет аллокаций, O(1) на шаг, один только обмен туда-обратно.
- **Копия при добавлении** — `append([]int{}, nums...)` обязательна, иначе все результаты укажут на один мутирующий `nums`.
- **Дубли исключаются самой структурой.** В swap — потому что каждая позиция заполняется уникальным элементом; visited/удаление — по той же причине.
- **Порядок перестановок разный** у трёх подходов — LeetCode принимает любой.

## Что пошло не так

1. **`maps.Clone` на каждом узле** — копировал всю мапу в каждой итерации, O(n!·n).
2. **`make` + два `copy` на каждом узле** — лишние аллокации в подходе с удалением.
