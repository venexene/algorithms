# Subsets

## Решение

### 1. Include/exclude — бинарный выбор

На каждом элементе два пути: взять его или пропустить. Результат добавляем **только в листе** (`i == len(nums)`).

```go
func dfs(i int, set []int) {
    if i == len(nums) {
        res = append(res, append([]int{}, set...)) // копия
        return
    }
    set = append(set, nums[i])  // include
    dfs(i+1, set)
    set = set[:len(set)-1]      // откат
    dfs(i+1, set)               // exclude
}
```

Каждое подмножество соответствует ровно одной цепочке решений «взять/не взять» — дублей нет, visited не нужен.

### 2. Start-index — движение только вперёд

Результат добавляем **на каждом узле**, а цикл стартует с `start`, чтобы не возвращаться к уже пройденным индексам.

```go
func dfs(start int, set []int) {
    res = append(res, append([]int{}, set...)) // каждый узел — подмножество
    for i := start; i < len(nums); i++ {
        set = append(set, nums[i])
        dfs(i+1, set)
        set = set[:len(set)-1]
    }
}
```

| | include/exclude | start-index |
|---|-----------------|-------------|
| Когда добавляем | только в листе | на каждом узле |
| Ключ от дублей | бинарный выбор | `for i := start` |
| Порядок результата | пустое в конце | пустое в начале |
| Куда ещё | Permutations, Combination Sum | генерация комбинаций |

## Главная ловушка Go: слайсы-ссылки

Слайс — это указатель на подлежащий массив, а не копия данных.

1. **`append(set, nums[i])` может писать в общий массив** — если `cap > len`, новый массив не выделяется, и ветки делят память.
2. **`res = append(res, set)` сохраняет ссылку, а не копию** — если массив потом мутирует, сохранённый ответ меняется.

### Фиксы

- **Копия при добавлении**: `append([]int{}, set...)` — каждый результат в своём массиве.
- **Явный откат**: `set = set[:len(set)-1]` после ветки include — вместо неявного поведения `append`.

Старт с `[]int{}` (cap 0) «чинит» проблему случайно — каждый `append` реаллоцирует. Но это везение, а не гарантия языка.

## Что пошло не так

1. **Добавлял `set` на каждом узле в include/exclude** — тот же `set` проходил через ветку exclude и добавлялся повторно → дубли. В include/exclude добавление только в листе.
2. **Не копировал при добавлении** — все записи в `res` указывали на один мутирующий слайс.
3. **`append(set, nums[i])` без явного отката** — ветки include/exclude делили подлежащий массив.
