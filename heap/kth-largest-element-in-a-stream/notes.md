# Kth Largest Element in a Stream

## Решение

### Min-heap размера k — O(log k) на add, O(k) памяти

Держим min-heap ровно из k элементов. Корень кучи (минимум) — это k-й по величине элемент потока.

При добавлении числа:
1. `heap.Push` — кладём элемент
2. Если размер кучи > k — `heap.Pop` удаляем минимум

После этого в куче k наибольших элементов, а корень — наименьший из них, то есть k-й по величине.

## Ключевая идея

Инверсия задачи: вместо поиска k-го наибольшего «сверху» держим **k наибольших снизу**. Min-heap, потому что удаляя минимум, сохраняем максимумы.

```
Поток: 4, 5, 8, 2 ...  k = 3

Heap (min): [4]
Heap (min): [4, 5]
Heap (min): [4, 5, 8]
Heap (min): [4, 5, 8] → push 2 → [2, 4, 5, 8] → size > 3 → pop → [4, 5, 8]
Корень = 4 (3-й по величине среди 4, 5, 8, 2) ✅
```

## Что важно запомнить

- **Min-heap для k-го наибольшего** (корень — минимум, он же ответ). Для k-го наименьшего — наоборот, max-heap.
- **Держим ровно k элементов.** Push → если > k → Pop. Это O(log k), а не O(n log n) на каждый вызов.
- **`Peek` = корень = `nums[0]`.** Для min-heap это минимум без удаления.
- **Инициализация кучи через тот же `Add`.** Не надо отдельной логики — просто прогоняем стартовый массив через тот же метод.
