# Kth Largest Element in Array

## Решение

### Min-heap размера k — O(n log k), O(k)

Держим min-heap ровно из k элементов. Проходим по массиву: push → если размер > k → pop. После полного прохода корень кучи (минимум из k наибольших) — ответ.

Та же идея, что в задаче про поток, но массив уже дан целиком.

```
nums = [3, 2, 1, 5, 6, 4], k = 2

Heap: [3] → [2, 3] → [2, 3] (1 не прошёл, size = k) → [3, 5] → [5, 6] → [5, 6]
Корень = 5 (2-й по величине) ✅
```

## Альтернативное решение

### 1. QuickSelect — O(n) среднем, O(1) памяти

Частичная сортировка на основе partition из QuickSort. Выбираем pivot, разбиваем массив: слева элементы больше pivot, справа — меньше. Если pivot встал на позицию `k-1` — он и есть k-й по величине. Иначе рекурсивно идём в нужную половину.

| | Heap | QuickSelect |
|---|------|-------------|
| Время (среднее) | O(n log k) | O(n) |
| Время (худшее) | O(n log k) | O(n²) |
| Память | O(k) | O(1) |
| Сложность кода | проще | сложнее (partition, индексы) |

QuickSelect быстрее в среднем и без доп. памяти, но худший случай O(n²) и тонкая работа с индексами. Для собеса heap-вариант — надёжный стандарт, QuickSelect — как бонус «знаю и могу».

### 2. Сортировка — O(n log n), O(1)

Просто отсортировать и взять `nums[n-k]`. Самое простое, но медленнее кучи. Годится как brute-force для сверки ответа.

## Что важно запомнить

- **Min-heap для k-го наибольшего** (удаляем минимум — остаются максимумы). Для k-го наименьшего — max-heap.
- **Размер кучи строго k.** Push → if size > k → Pop. Это ключевой трюк, дающий O(log k) на элемент.
- **Корень = `Peek()` = `nums[0]`** — без удаления.
- **Guard `k > len(nums)`** — иначе куча не наберёт k элементов и ответ неопределён.

## Что пошло не так

1. **Нет проверки `k > len(nums)`.** Если k больше размера массива, в куче остаётся меньше k элементов, и `Peek()` вернул бы не то. Добавил ранний возврат `-1`.
