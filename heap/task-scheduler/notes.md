# Task Scheduler

## Решение 1: Max-heap + очередь кулдауна — симуляция

Моделируем каждый тайм-слот:

1. **Max-heap частот** — корень самая частая задача
2. **Очередь waiters** — задачи на кулдауне, с полем `w` (сколько слотов осталось до возврата)

Цикл (одна итерация = один слот времени):
- Декрементируем `w` у всех waiters; кто дозрел (`w == 0`) — возвращаем в кучу
- Если куча пуста — простой (`res++`, continue)
- Иначе `pop` самую частую, выполняем, при остатке > 0 кладём в waiters с `w = n+1`

Сложность: O(res × m), где m ≤ 26 (типы задач), res = итоговое время. Память O(m).

## Решение 2: Жадная формула — O(n), без симуляции

Симуляция избыточна — простой считаются по одному, а при большом n их большинство. Ответ можно вычислить напрямую:

```
maxCount      = максимальная частота задачи
maxCountTasks = сколько задач имеют эту частоту

answer = max(len(tasks), (maxCount-1)*(n+1) + maxCountTasks)
```

### Откуда формула

Возьми самую частую задачу (A, 3 раза, n=2) и разложи каркасом:

```
A _ _ A _ _ A
```

Это `(maxCount-1)` блоков по `(n+1)` слотов + последний A. В пустые слоты вставляем остальные задачи. Если задач больше, чем свободных слотов — простоев нет, и ответ просто `len(tasks)`. Поэтому берём `max`.

```
[ A, A, A, B, B, B ], n=2
maxCount = 3 (A и B), maxCountTasks = 2
answer = max(6, (3-1)*(2+1) + 2) = max(6, 8) = 8  ✅
```

```
[ A, A, A, B, B, B, C ], n=2
maxCount = 3, maxCountTasks = 2
answer = max(7, 2*3 + 2) = max(7, 8) = 8  ✅
```

| | Симуляция (heap) | Формула |
|---|------------------|---------|
| Время | O(res) | O(n) |
| Память | O(m) | O(1) |
| Идея | пошаговое моделирование | математический подсчёт |
| Когда | универсально, наглядно | нужна скорость |

## Что важно запомнить

- **Каркас из самой частой задачи.** `(maxCount-1) × (n+1) + maxCountTasks` — это длина расписания, если самая частая задача диктует простои.
- **`max(len(tasks), ...)`** — если задач больше, чем слотов в каркасе, простоев нет и ответ = общее число задач.
- **Кулдаун `w = n+1` в симуляции.** Между двумя выполнениями задачи должно быть n слотов, поэтому после выполнения она возвращается через n+1 слотов.
- **`range` копирует элемент.** Для мутации слайса — `waiters[i].w--`, не `wait.w--`.

## Что пошло не так

1. **`range` копия**: `for i, wait := range waiters { wait.w-- }` — декрементировал копию, `w` никогда не обнулялся.
2. **Удаление из слайса**: `append(waiters[i:], waiters[:i+1]...)` — дублирует вместо удаления. Правильно `append(waiters[:i], waiters[i+1:]...)`, но при `range` надёжнее строить новый слайс.
3. **Кулдаун `w = n` вместо `n+1`** — задача выполнялась на слот раньше нужного (между повторами n-1 слотов вместо n).
4. **Симуляция даёт ~15% перцентиль** — при большом n простои пересчитываются по одному. Формула считает ответ напрямую за O(n).
