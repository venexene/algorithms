# K Closest Points to Origin

## Решение

### Max-heap размера k — O(n log k), O(k)

Держим max-heap из k ближайших точек. Корень — самая дальняя из них. Проходим по всем точкам: push → если размер > k → pop самую дальнюю. После прохода в куче k ближайших.

Важно: сравниваем **квадраты расстояний**, а не сами расстояния.

## Сравнение расстояний без sqrt

`√a > √b` ⟺ `a > b`, потому что корень монотонно возрастает. Значит `sqrt` не нужен — достаточно сравнить:

```
расстояние² = x*x + y*y
```

- Целочисленная арифметика вместо float64
- `x*x` вместо `math.Pow(x, 2)` — в разы быстрее
- Нет переполнения: координаты ≤ 10⁴, значит квадрат расстояния ≤ 2·10⁸

## Альтернативные решения

### 1. Сортировка — O(n log n), O(1)

Отсортировать точки по квадрату расстояния и взять первые k. Проще всего, но медленнее кучи (полная сортировка вместо частичной).

### 2. QuickSelect — O(n) среднем, O(1) памяти

Partition как в QuickSort: выбираем pivot, точки слева ближе, справа дальше. Если pivot на позиции k — левая часть и есть ответ. Быстрее в среднем, но худший случай O(n²) и тонкая работа с индексами.

### 3. Min-heap всех точек — O(n log n), O(n)

Кладём все n точек в min-heap, потом k раз `Pop`. Хуже max-heap размера k по памяти (O(n) против O(k)) и времени, но проще для понимания: «извлекаем k ближайших по порядку».

| | Время | Память | Когда |
|---|-------|--------|-------|
| Max-heap (k) | O(n log k) | O(k) | основной вариант |
| Сортировка | O(n log n) | O(1) | brute-force для сверки |
| QuickSelect | O(n) среднее | O(1) | нужен максимум скорости |
| Min-heap (n) | O(n log n) | O(n) | избыточно |

## Что важно запомнить

- **Max-heap для k ближайших** (корень — самая дальняя, её и удаляем). Для k дальних — min-heap.
- **Квадрат расстояния вместо расстояния.** Убирает `sqrt`/`pow`/float — колоссальный прирост скорости (с 5% до ~90% перцентиля).
- **Порядок в heap-массиве не важен** — `h.points` возвращается в heap-раскладке, не отсортированным. Задача принимает любой порядок; если нужен отсортированный — извлекай через `heap.Pop`.

## Что пошло не так

1. **`math.Sqrt(math.Pow(...))` в `Less`.** Вычислялся на каждое сравнение в куче (O(log k) раз на операцию) — float-математика убивала скорость. LeetCode показал 5% перцентиль.
2. Исправил на `sqrDist` с целочисленным `x*x + y*y` — скорость выросла на порядок.
