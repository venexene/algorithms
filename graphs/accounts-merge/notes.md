# Accounts Merge

## Решение

### DSU (Union-Find) — O(E log E), O(E + n)

Ключевая идея: аккаунты с общим email — это **одна компонента связности**. Объединяем аккаунты через DSU:

1. `emailToIdx`: email → индекс первого аккаунта, где он встретился.
2. Для каждого email, если он уже встречался в другом аккаунте — `Union(первый, текущий)`.
3. Группируем emails по корню (`Find(i)`), дедуплицируем через `map[string]bool`.
4. Для каждой группы: имя + отсортированные уникальные emails.

DSU: `Find` с path compression, `Union` по размеру.

## Альтернативные подходы

### 1. Граф + DFS/BFS

Строим двудольный граф: узлы — аккаунты и emails, рёбра — «аккаунт содержит email». Компоненты связности (через DFS или BFS) = итоговые аккаунты. Та же асимптотика, но кода больше.

### 2. Ручное слияние групп (без DSU)

Можно хранить `email → список аккаунтов` и сливать группы вручную (например, BFS от email). По сути то же самое, что DSU, но менее удобно для многократных объединений.

## Асимптотика

Пусть `n` — число аккаунтов, `E` — общее число email-вхождений (с учётом повторений), `k` — число уникальных email.

- **Union-Find**: `Find` с path compression и `Union` по размеру дают почти O(1) на операцию — обратная функция Аккермана `α(n)`. Суммарно по всем `Union`/`Find` — O(E · α(n)).
- **Группировка**: O(E) — один проход по всем email для сбора в группы.
- **Сортировка**: каждая группа размера `k_i` сортируется за O(k_i log k_i); суммарно O(E log E) в худшем случае (когда всё слилось в одну группу).

Итог:
- **время: O(E log E)** — доминирует сортировка;
- **память: O(E + n)** — `emailToIdx`, `rootToEmail`, `roots` и массивы DSU.

## Что важно запомнить

- **Задача про компоненты связности** — «у аккаунтов есть общий email» = «аккаунты в одной компоненте». DSU — самый удобный инструмент.
- **DSU = Union-Find**: `Find` с path compression, `Union` по размеру (или рангу).
- **`map[int]map[string]bool`** — вложенную map нужно инициализировать перед записью, иначе nil map panic.
- **Сортировка + дедупликация emails** — обязательные требования задачи.
- **Имя берём из корневого аккаунта** — по условию у слитых аккаунтов одинаковое имя.
