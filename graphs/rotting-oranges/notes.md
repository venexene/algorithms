# Rotting Oranges

## Решение

### Многоисточниковый BFS по уровням — O(n·m), O(n·m)

Собираем в очередь все изначально гнилые апельсины (2) и считаем свежие (1) в `orangesNum`. Запускаем BFS волнами: за одну итерацию обрабатываем все апельсины текущей волны (`orangesInMinute := len(queue)`), заражаем соседей, уменьшаем `orangesNum`. `minute` считает уровни (старт с -1, т.к. начальные гнилые — это 0 минут). В конце `orangesNum == 0` → вернуть `minute`, иначе -1.

## Что важно запомнить

- **Без финального прохода по сетке** — вместо повторного сканирования в конце держим счётчик `orangesNum` и уменьшаем при каждом заражении. В конце достаточно `orangesNum == 0`.
- **Граница уровня** — `orangesInMinute := len(queue)` фиксирует размер текущей волны, чтобы не смешивать уровни BFS.
- **`minute := -1`** — после первой волны становится 0: начальное заражение не требует минут.
- **Многоисточниковый BFS** — все начальные гнилые кладём в очередь сразу, а не запускаем BFS для каждого по отдельности.
- Краевые случаи: пустая сетка → 0 (защитная проверка), все гнилые → 0, все свежие без гнили → -1.

## Микрооптимизации

1. **`queue = queue[1:]`** — сдвиг головы очереди через реслайс. O(1) на операцию, но голова не освобождается: backing array держит все когда-либо добавленные позиции. Для BFS допустимо; строгая альтернатива — индекс `head` или `container/list`.
2. **`[]int{i, j}` на каждую позицию** — аллокация слайса на каждый enqueue. Можно кодировать позицию одним интом `i*m+j` или парой `[2]int`, чтобы избежать лишних аллокаций. Влияние на скорость заметно только на больших сетках.
3. **Четыре явные проверки направлений** — быстрее, чем обход через массив `dirs := [][]int{{...}}` (нет лишних аллокаций/итераций), но код повторяющийся. Компромисс: `dirs` — читаемее, явные проверки — быстрее.
