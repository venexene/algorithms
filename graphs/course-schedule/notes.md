# Course Schedule

## Решение

### Topological sort через DFS с тремя состояниями visited — O(V + E), O(V)
0 = не посещён, 1 = в текущем DFS-пути, 2 = обработан. Зашли в курс → 1. Для каждого соседа: если 1 → цикл. Если 0 → рекурсия. Если рекурсия нашла цикл → return false. После всех соседей → 2, return true. Внешний цикл по всем курсам — граф может быть несвязным.

## Почему три состояния, а не два (visited/unvisited)
Двух состояний недостаточно: visited/unvisited не различает «уже обработан» и «в процессе». Если курс уже обработан (состояние 2) — цикла нет, можно пропустить. Если в процессе (состояние 1) — цикл найден. С двумя состояниями мы бы ложно детектили цикл на уже обработанных курсах.

## Что важно запомнить

### Направление рёбер
`prerequisites[i] = [ai, bi]` — чтобы взять ai, нужно сначала bi. Направление: `bi → ai`. `adj[bi].append(ai)`. Не наоборот, не двусторонне.

### DFS с возвратом
```go
if visited[c] == 0 {
    if !canFinishAdd(adj, visited, c) {
        return false  // цикл в поддереве
    }
}
```
Не `return canFinishAdd(...)` — это выйдет после первого соседа, не проверив остальные.

### Порядок отметок
Зашли → 1 → обошли всех соседей → 2. Никогда не 2 до завершения обхода.

## Что пошло не так
1. Двусторонние рёбра вместо направленных `bi → ai`
2. `return canFinishAdd(...)` вместо проверки на false — выходил после первого соседа
3. Пытался отслеживать `prev` и сравнивать глубину — избыточно, три состояния проще
