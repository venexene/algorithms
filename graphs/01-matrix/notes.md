# 01 Matrix

## Решение

### Multi-source BFS — O(m·n), O(m·n)

Инициализируем `res` значением `-1` («не посещено»). Все нулевые ячейки кладём в очередь с `res = 0`, затем BFS по уровням: для каждого соседа с `res == -1` ставим `res = lenPath` (текущий уровень) и добавляем в очередь. Каждая ячейка обрабатывается один раз — отдельный `visited` не нужен, его роль играет сам `res`.

Ключевая идея — **развернуть направление**: не BFS от каждой единицы к нулю (O((m·n)²)), а одна волна от всех нулей сразу.

### Альтернатива: DP двумя проходами — O(m·n), O(1) доп. памяти

Можно без очереди, динамикой. Расстояние до ближайшего нуля раскладывается на пути, идущие только сверху/слева и только снизу/справа.

1. Инициализируем `res`: нули → `0`, единицы → `+∞` (большое число).
2. **Проход сверху-слева вниз-вправо:** `res[i][j] = min(res[i][j], res[i-1][j]+1, res[i][j-1]+1)` — пути сверху и слева.
3. **Проход снизу-справа вверх-влево:** `res[i][j] = min(res[i][j], res[i+1][j]+1, res[i][j+1]+1)` — пути снизу и справа.

После двух проходов в каждой ячейке минимальное расстояние. Дополнительной памяти, кроме результата, не нужно.

## Что важно запомнить

- **Multi-source BFS** — когда источников несколько, клади их все в очередь сразу; одна волна от всех даёт кратчайшие расстояния за один проход.
- **`res` сам может быть visited** — инициализируй «не посещено» отдельным значением (`-1`), тогда не нужен отдельный `map`/`bool`-слайс.
- **BFS по уровням**: инкремент расстояния (`lenPath++`) перед обработкой уровня, а не на каждую ячейку.
- **Два семейства решения**: BFS (интуитивно, нужна очередь) vs DP двумя проходами (без очереди, O(1) доп. памяти). Оба O(m·n).

## Что пошло не так

- Сначала запускал BFS **от каждой единицы** — O((m·n)²), TLE.
- В BFS не было `visited` — очередь раздувалась до OOM (`runtime: cannot allocate memory`).
- `visited` помечал при извлечении, а не при добавлении — дубли в очереди.
