# Design Add and Search Words Data Structure

## Решение

### Trie + DFS для wildcard `.`

Структура — обычный trie на `[26]*Node` + `isEnd`. Отличие от Implement Trie — поиск с `.` (джокером, любая буква).

- **AddWord**: стандартная вставка.
- **Search**: обёртка, вызывает DFS с корня.
- **SearchDFS(word, node)**: идём по слову:
  - обычная буква → спуск `children[r-'a']`, если nil — false
  - `.` → пробуем **каждый** непустой `child`, рекурсивно ищем остаток `word[i+1:]`

## Ключевая идея

Точка = ветвление. Вместо одного перехода вниз пробуем все 26 направлений. Это DFS по trie, где `.` открывает несколько путей одновременно.

```
word = "b.d", trie содержит "bad", "bid"

b → узел B
. → ветвимся в детей: a (→ "ad" → d → isEnd ✅), i (→ "id" → d → isEnd ✅)
```

## Что важно запомнить

- **Публичный метод — обёртка, логика — в DFS.** `Search` одной строкой вызывает `SearchDFS(word, root)`. Это убирает дублирование без изменения сигнатуры.
- **`word[i+1:]` не копирует строку** — в Go срез строки создаёт новый заголовок на те же байты, O(1). Можно не бояться резать строку в рекурсии.
- **`res = res || dfs(...)`** — корректно, но после первого `true` остальных детей можно не проверять (короткое замыкание спасает от лишних вызовов, но не от лишних итераций).
- **Сложность с точками экспоненциальна в худшем случае** — слово из одних `.` ветвится на 26 в каждом уровне. Это нормально для задачи, стандартное решение такое же.
