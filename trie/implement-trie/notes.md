# Implement Trie (Prefix Tree)

## Решение

### Trie на массиве `[26]*Node` — O(L), O(26·N)

Каждый узел хранит:
- `children [26]*Node` — указатели на дочерние узлы по индексу `r - 'a'`
- `isEnd bool` — конец слова

Операции:
- **Insert**: идём по символам, создаём узлы лениво, в конце ставим `isEnd = true`
- **Search**: идём по символам; если путь оборвался — false. В конце проверяем `isEnd` (не просто «путь есть», а «слово целиком»)
- **StartsWith**: идём по символам; если путь оборвался — false. Иначе true

## Почему массив, а не map

- `[26]*Node` — O(1) доступ по символу, без хеширования
- Фиксированные 26 слотов на узел — для lowercase-латиницы идеально
- `map[byte]*Node` дал бы меньше памяти на разреженных данных, но медленнее и избыточен для этой задачи

## Что важно запомнить

- **`Search` vs `StartsWith` отличаются только `isEnd`.** Путь одинаковый, разница — надо ли проверять, что слово закончилось.
- **Итерация по строке даёт rune напрямую** — `for _, r := range word`, не нужен `[]rune(word)`.
- **Ленивое создание узлов** — создаём только те узлы, которые реально встречаются в словах.
- **Нулевые значения** — `&Node{}` достаточно, `children` и `isEnd` и так nil/false.

## Что пошло не так

1. **`[]rune(word)`** — избыточная конвертация в слайс и лишняя аллокация. Строку можно итерировать напрямую, `r` уже rune.
2. **Явная инициализация** — `children: [26]*Node{}, isLeaf: false` повторяет нулевые значения, достаточно `&Node{}`.
3. **`isLeaf` → `isEnd`** — точнее отражает смысл: узел помечает конец слова, а не «лист» (у него могут быть дети).
