# Validate Binary Search Tree

## Инсайт

BST проверяется не локально (узел vs дети), а глобально: **всё левое поддерево** должно быть меньше корня, **всё правое** — больше. Один узел может быть валиден относительно своего родителя, но нарушать условие для деда.

```
    5
   / \
  3   8
 / \
1   6     ← 6 > 3 (ок для родителя), но 6 > 5 (нарушение для корня!)
```

## Решение

### Передача диапазона сверху вниз — O(n), O(h)
Каждый узел получает разрешённый диапазон `(min, max)`. Если `Val` вне диапазона — false. Левый потомок: `(min, Val)`. Правый: `(Val, max)`. Корень: `(MinInt64, MaxInt64)`.

## Что важно запомнить
- Диапазоны спускаются СВЕРХУ и СУЖАЮТСЯ с каждым шагом. Не вычислять снизу.
- `<=` и `>=`, не `<` и `>` — дубликаты не разрешены в BST.
- `math.MinInt64/MaxInt64` для начальных границ — покрывает весь диапазон int.
- Empty поддерево (nil) — валидный BST.

## Что пошло не так
1. Пытался вычислить границы снизу вверх через указатели и `max`/`min` — они не обновлялись
2. Инициализировал `min=max=root.Val` — корень не проходил собственную проверку
3. Передавал `min`/`max` по значению — изменения терялись
4. Проверял `Val` ПОСЛЕ рекурсии, а не до — невалидный узел мог быть пропущен
