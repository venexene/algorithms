# Time Based Key-Value Store

## Решение

### Слайс пар + бинарный поиск (last ≤ target) — Set O(1), Get O(log n), O(n)

Храним `map[string][]TimeValue`, где `TimeValue` — пара `{value, timestamp}`.

**Ключевая гарантия задачи:** для одного ключа `Set` вызывается со строго возрастающими `timestamp`. Поэтому записи в слайсе всегда отсортированы — `Set` это просто `append` в конец за O(1).

`Get(key, timestamp)` ищет наибольший `timestamp ≤ target` бинарным поиском (паттерн «последний подходящий» с переменной `ans`): закрытый интервал `[0, n-1]`, условие `left <= right`. Если `a[mid].timestamp <= target` — запоминаем `ans = mid` и идём вправо, иначе `right = mid - 1`. Пустой ключ → `""`.

## Что важно запомнить

- **Читай ограничения.** «timestamp строго возрастают» — главный ключ к выбору структуры: не нужны мапа по timestamp, сортировка или куча.
- **`append` к `nil`-слайсу работает** — `map[key] = append(map[key], v)` не требует предварительной инициализации.
- **«Наибольший ≤ target» = last ≤ target с `ans`.** После цикла ответ лежит в `ans`, не нужно вычислять `left-1` и ловить границы.
- **Две схемы бинарного поиска нельзя смешивать:**
  - граничный поиск (lower/upper bound): полуинтервал `[0, n]`, `left < right`, сдвиги `mid` / `mid+1` — **без `mid-1`**;
  - точный поиск / `ans`-паттерн: закрытый интервал `[0, n-1]`, `left <= right`, сдвиги `mid±1` — здесь `mid-1` корректен.
- **Проверка пустого ключа обязательна** — иначе бинарный поиск на пустом слайсе даст панику или неверный ответ.

## Паттерны бинарного поиска

Шпаргалка по основным схемам. Главное — не смешивать два семейства: **граничный поиск** (полуинтервал `[0, n]`) и **точный/`ans`** (закрытый интервал `[0, n-1]`).

### 1. Classic — точное вхождение

Поиск `== target`. Закрытый интервал, возврат индекса или `-1`.

```go
left, right := 0, n-1
for left <= right {
    mid := left + (right-left)/2
    if a[mid] == target { return mid }
    if a[mid] < target { left = mid+1 } else { right = mid-1 }
}
return -1
```

### 2. Lower bound — первый `≥ target`

Полуинтервал `[0, n]`, `left < right`, **без `mid-1`**. После цикла `left` — первый `≥ target` (или `n`).

```go
left, right := 0, n
for left < right {
    mid := left + (right-left)/2
    if a[mid] >= target { right = mid } else { left = mid+1 }
}
// ответ: left
```

### 3. Upper bound — первый `> target`

Как lower bound, но условие `>`:

```go
if a[mid] > target { right = mid } else { left = mid+1 }
// left — первый > target; последний ≤ target = left-1
```

### 4. Last ≤ target — последний подходящий (`ans`)

То, что использовано в этой задаче. Закрытый интервал, ответ копится в `ans`.

```go
left, right, ans := 0, n-1, -1
for left <= right {
    mid := left + (right-left)/2
    if a[mid] <= target { ans = mid; left = mid+1 } else { right = mid-1 }
}
// ответ: ans (или -1)
```

### 5. Find first true — монотонный предикат

Массив неявно разбит на `false...false true...true`, нужна первая `true` (например, `First Bad Version`). Это lower bound по предикату.

```go
left, right := 0, n
for left < right {
    mid := left + (right-left)/2
    if predicate(mid) { right = mid } else { left = mid+1 }
}
// left — первая true
```

### 6. Binary search on answer — поиск значения

Ищем не индекс, а число в диапазоне `[low, high]`. Работает, когда ответ монотонен: «если `x` подходит, то и всё больше/меньше тоже». Задачи: `Sqrt(x)`, `Koko Eating Bananas`, `Split Array Largest Sum`. Суть: бинарный поиск по числу + проверка `can(x)`.

### 7. Rotated sorted array

Массив отсортирован, но повёрнут. Ключ — определять, какая половина отсортирована, и решать, в какой искать. Отдельный приём, не сводится к границам.

### 8. Find peak

Сравниваем `mid` с соседом и идём в сторону возрастания. Работает даже на неупорядоченном массиве (`Find Peak Element`).

### Сводная таблица

| Паттерн | Ищет | Границы | Условие | Сдвиги |
|---|---|---|---|---|
| Classic | `== target` | `[0, n-1]` | `<=` | `mid±1` |
| Lower bound | первый `≥` | `[0, n]` | `<` | `mid`, `mid+1` |
| Upper bound | первый `>` | `[0, n]` | `<` | `mid`, `mid+1` |
| Last `≤` (ans) | последний `≤` | `[0, n-1]` | `<=` | `ans` + `mid±1` |
| First true | первая `true` | `[0, n]` | `<` | `mid`, `mid+1` |
| On answer | значение | `[min, max]` | `<=`/`<` | по предикату |

**Правило на 90% проблем:** граничный поиск → `[0, n]`, `left < right`, никаких `mid-1`. Точный/`ans` → `[0, n-1]`, `left <= right`, `mid±1`. Смешивание двух схем — главный источник off-by-one.

## Что пошло не так

- Пропустил условие «timestamp строго возрастают» → сначала искал решение с неупорядоченной мапой.
- Пытался бинарным поиском искать по `map[int]string` — бинарный поиск применим только к отсортированным данным.
- Смешал схемы: `for left < right` вместе с `right = mid - 1` — пропускал кандидата (например, `[1,2,3,4]`, `target=2` возвращал `1`).
- В upper bound брал `right := len-1` вместо `len` — не проверялся последний элемент, а слайс из одного элемента всегда давал `""`.
- Итог: перешёл на `last ≤ target` с `ans` — явный ответ без off-by-one.
