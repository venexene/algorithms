# Find Minimum in Rotated Sorted Array

## Решение

### Бинарный поиск — O(log n), O(1)
Сравниваем `nums[mid]` с `nums[high]`. Условие `low < high`. Возвращаем `nums[low]`.

## Почему `high = mid`, а `low = mid + 1`

Сравниваем `nums[mid]` с `nums[high]`, потому что `high` всегда находится **после** разрыва (или разрыва нет и массив полностью отсортирован). 

### Случай `nums[mid] < nums[high]`

```
[4, 5, 0, 1, 2, 3]
         ↑mid  ↑high
nums[mid]=1 < nums[high]=3 → правая половина [1,2,3] сортирована
```

Минимум не может быть в правой половине (там все элементы больше mid). Но mid сам МОЖЕТ быть минимумом. Поэтому `high = mid` (не `mid - 1`) — не исключаем mid.

### Случай `nums[mid] > nums[high]`

```
[4, 5, 6, 7, 0, 1]
      ↑mid       ↑high
nums[mid]=7 > nums[high]=1 → разрыв справа
```

Минимум точно справа от mid, и mid точно НЕ минимум. Поэтому `low = mid + 1` — исключаем mid.

### Почему `low < high`, не `<=`

Когда `low == high` — диапазон схлопнулся до одного элемента. Это и есть минимум. Цикл заканчивается, `return nums[low]`.

## Что важно запомнить
- Сравниваем `nums[mid]` с `nums[high]`, не с `nums[low]`. `high` всегда в сортированной части или после разрыва.
- `high = mid` когда mid может быть ответом. `low = mid + 1` когда mid точно не ответ.
- Условие `low < high` — без `=`, один элемент это ответ.
