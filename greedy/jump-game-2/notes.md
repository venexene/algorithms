# Jump Game II

## Инсайт

Greedy BFS-уровнями: `mx` — граница текущего прыжка, `mx2` — граница следующего. Когда выходим за `mx` (индекс `i` больше не достижим текущим прыжком) — увеличиваем счётчик и переключаемся на `mx2`. Ключевое: `mx2` обновляется *безусловно* на каждом индексе.

## Решение

### Greedy с двумя границами — O(n), O(1)

`mx` — самый дальний индекс, достижимый текущим количеством прыжков. `mx2` — самый дальний индекс, достижимый следующим прыжком. Идём по массиву: если `mx < i` — `res++`, `mx = mx2`. После проверки всегда обновляем `mx2 = max(mx2, i + nums[i])`.

## Что важно запомнить

- **Структура BFS-уровнями:** каждый прыжок — это уровень. `mx` — граница уровня, `mx2` — накопленная граница следующего. Переключение уровней когда `i` выходит за `mx`
- **`mx2` обновляется всегда.** Даже после переключения `mx = mx2` — текущий индекс `i` теперь достижим и может расширить *следующий* уровень
- **Ранний выход `mx >= n-1`** — если текущий прыжок уже достигает конца, нет смысла считать дальше
- **База `len == 1 → 0`:** мы уже на месте, прыжков не нужно
- **Тот же паттерн что Jump Game I**, но там `true/false`, здесь — количество прыжков. Jump Game I = «долетит ли?», Jump Game II = «сколько прыжков?»

## Что пошло не так

1. **`mx2` обновлялся только в `if`-ветке** (`mx >= i`). Когда `mx < i` и происходило переключение на следующий уровень, индекс `i` не учитывался в `mx2`. Контрпример: `[1,1,3,1,1]` — после первого прыжка на индекс 2 с `nums[2]=3` его вклад игнорировался, ответ завышался
2. **Решение в одной строке от правильного** — структура `mx`/`mx2`/`res++` была верной, ошибка чисто в размещении `mx2 = max(...)`
