# Partition Labels

## Инсайт

Граница фрагмента = максимум индексов последнего вхождения всех букв, встреченных на этом фрагменте. Как только `i` доходит до этой границы — фрагмент закрывается. Два прохода: первый — `last[буква]`, второй — greedy-разбиение.

## Решение

### Greedy с last-индексами — O(n), O(1)

Первый проход: для каждой буквы запоминаем индекс последнего появления. Второй проход: `end = max(end, last[v])`. Когда `i == end` — найден фрагмент, добавляем длину `end - start + 1`, сдвигаем `start = i + 1`.

## Что важно запомнить

- **Это greedy, не DP.** Нет рекуррентного соотношения, нет выбора. Граница фрагмента жёстко задана последними вхождениями букв. Попытка решить через DP ведёт в тупик
- **Два прохода, не один.** Невозможно узнать границу фрагмента, не зная всех last-индексов. Первый проход — сбор информации, второй — разбиение
- **`end = max(end, last[v])`** — граница отодвигается вправо каждый раз, когда встречается буква с более поздним последним вхождением
- **Память O(1):** 26 строчных букв → массив `[26]int` вместо map. Но map тоже ок

## Что пошло не так

1. **Пытался решить как DP в один проход** — задача не имеет DP-структуры. Нет оптимальной подструктуры: фрагменты не зависят от предыдущих решений, их границы предопределены last-индексами. Это ключевой момент: не каждая задача на разбиение — DP
2. **Понадобилась подсказка про границу = max(last)** — после этого реализация пошла сразу. Ошибка была в классификации задачи, а не в написании кода
