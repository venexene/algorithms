# Jump Game

## Инсайт

Это не DP, а greedy. Достаточно отслеживать `mx` — самую дальнюю позицию, до которой можно добраться на текущий момент. На каждом шаге: если `mx >= i`, обновляем `mx = max(mx, i + nums[i])`. Один проход, O(n).

## Решение

### Greedy — O(n), O(1)

Переменная `mx` хранит максимальный индекс, до которого можно допрыгнуть. Идём слева направо: если `mx >= i` (до текущего индекса можно добраться) — обновляем `mx`. Если `mx >= n-1` — ранний выход `true`. После цикла — проверка `mx >= n-1`.

## Что важно запомнить

- **Jump Game = greedy, не DP.** Интуитивно хочется `dp[i] = можно ли достичь i`, но это O(n²). Greedy-подход: «как далеко я могу прыгнуть прямо сейчас?» — O(n)
- **`mx >= i` — ключевое условие.** Если до текущей позиции нельзя допрыгнуть, то все дальнейшие тоже недостижимы. Без этой проверки решение некорректно
- **Ранний выход `mx >= n-1`** — ускоряет, но не обязателен. Достаточно проверки в конце
- **Этот же greedy используется в Jump Game II** (минимальное количество прыжков) — паттерн масштабируется

## Что пошло не так

1. **DP с массивом булов** — `dp[i] = true/false`, вложенный цикл по всем длинам прыжка. O(n²) → TLE на больших входных данных
2. **Не сразу увидел greedy** — задача классифицируется как DP только в учебных материалах. На деле жадный подход элегантнее и быстрее. Если решение требует O(n²) и TLE — подумай, можно ли заменить на один проход с отслеживанием максимума
