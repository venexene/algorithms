# Coin Change

## Инсайт

Это **полный перебор** всех монет для каждой суммы, а не жадный выбор одной монеты. `dp[i]` = минимум из `1 + dp[i - coin]` по всем `coin ≤ i`, где `dp[i-coin]` достижимо (≠ -1).

Ключевая ошибка: попытка взять *одну* монету (самую крупную) и нарастить от неё. Но задача требует перебрать *все* монеты и выбрать лучший вариант — классический DP с минимизацией.

## Решение

### DP с полным перебором — O(amount × len(coins)), O(amount)

`dp[i]` — минимальное количество монет для суммы `i`. База: `dp[0] = 0`. Для каждой суммы перебираем все монеты: если `coin ≤ i` и `dp[i-coin]` достижимо — кандидат `1 + dp[i-coin]`. Берём минимум.

Недостижимые суммы помечаем `-1`.

## Что важно запомнить

### Почему жадность не работает

Жадный выбор «бери самую крупную монету, которая влезает» даёт неправильный ответ. Контрпример: `coins=[1,3,4]`, `amount=6`.

- Жадно: 4 → остаток 2 → 1+1 = **3 монеты** (4+1+1)
- Оптимально: 3+3 = **2 монеты**

Жадность работает только для канонических систем монет (как обычные деньги: 1,2,5,10...). Для произвольного набора — только DP.

### DP-переход

`dp[i] = min(1 + dp[i-coin])` по всем `coin`. Не `dp[i] = 1 + dp[i-largestCoin]`. Принципиальная разница: пробуем *каждую* монету как последнюю в наборе для суммы `i`.

### Почему одномерный массив, а не двумерный

В отличие от Knapsack, здесь можно использовать одну и ту же монету сколько угодно раз (unbounded). Поэтому достаточно одномерного `dp` и прохода по суммам от 1 до amount — `dp[i-coin]` уже содержит лучший ответ для меньшей суммы, возможно с той же монетой.

### -1 как маркер недостижимости

Не `math.MaxInt` — при сложении `1 + MaxInt` будет переполнение. `dp[i] == -1` как начальное значение и проверка `dp[i-coin] != -1` перед использованием.

## Что пошло не так

1. **Жадный выбор одной монеты** — брал `coins[len(coins)-1]` (последнюю, после сортировки — крупнейшую) и искал первую, которая влезает. Это даёт ответ только если монеты канонические или если повезло с конкретным amount
2. **Не перебирал все монеты** — внутренний цикл был `c--` для поиска *одной* подходящей монеты, вместо `for _, coin := range coins` с выбором минимума
