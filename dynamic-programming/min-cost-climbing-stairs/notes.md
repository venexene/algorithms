# Min Cost Climbing Stairs

## Инсайт

Та же DP-формула что в Climbing Stairs, но с ценой: `cost[i] = cost[i] + min(cost[i-1], cost[i-2])`. На ступень `i` дешевле попасть либо с `i-1`, либо с `i-2`. Вершина находится за пределами массива, поэтому ответ — `min(cost[n-1], cost[n-2])`.

## Решение

### In-place DP — O(n), O(1)

Мутируем входной массив: `cost[i] += min(cost[i-1], cost[i-2])`. После цикла ответ — минимум из двух последних элементов: с вершины можно сделать шаг 1 (с `n-1`) или шаг 2 (с `n-2`).

База:
- `len == 0` → `0`
- `len == 1` → `cost[0]`
- `len == 2` → `min(cost[0], cost[1])`

Цикл начинается с `i=2`.

## Что важно запомнить

- **In-place DP** — накапливаем ответ прямо во входном массиве. Не нужны ни `dp[]`, ни `prev1/prev2`. Экономит и память, и строки кода
- **Вершина вне массива** — в отличие от Climbing Stairs, где `f(n)` это ответ, здесь вершина «после» последней ступени. Поэтому `min(cost[n-1], cost[n-2])`, а не `cost[n-1]`
- **Общий паттерн с Climbing Stairs:** `cost[i] += min(cost[i-1], cost[i-2])` — это `fib(i) = fib(i-1) + fib(i-2)`, но с минимумом вместо суммы
- **Мутация входа ок для LeetCode**, но в продакшене лучше не трогать исходные данные — использовать `prev1, prev2`
