# Longest Increasing Subsequence

## Инсайт

DP: `dp[i]` — длина LIS, заканчивающейся на `nums[i]`. Для каждого `i` перебираем все `j < i`: если `nums[j] < nums[i]`, то `dp[i] = max(dp[i], dp[j] + 1)`. Ответ — максимум по всему `dp`, не последний элемент.

## Решение

### DP O(n²), O(n)

Массив `dp`, каждое значение инициализируется 1 (подпоследовательность из одного элемента). Двойной цикл: внешний по `i`, внутренний по `j < i`. Глобальный максимум отслеживается в `res`.

## Что важно запомнить

- **LIS ≠ последовательные элементы.** Можно пропускать: `[4,10,4,3,8,9]` → `[4,8,9]`, длина 3, а не просто `[4,10]`
- **Ответ — max(dp), не dp[n-1].** LIS не обязана заканчиваться на последнем элементе. Контрпример: `[1,2,0]` — dp = `[1,2,1]`, ответ 2, а не 1
- **dp[i] инициализируется 1**, а не 0 — каждый элемент сам по себе образует подпоследовательность длины 1
- **Можно быстрее:** O(n log n) через паттерн patience sorting (массив `tails` + бинарный поиск), но O(n²) достаточно для большинства собеседований

## Что пошло не так

1. **Считал только последовательные возрастания** — `if nums[i-1] < nums[i]` увеличивал счётчик. Это не LIS, а длина непрерывного возрастающего отрезка
2. **Возвращал `dp[n-1]`** вместо максимума по `dp`. LIS не обязана заканчиваться на последнем индексе
